# SNS・AI の操作と制限（0.2.0）

## SNS を集める

「集める」→「SNSを追加」で調査名、種類、検索条件、フォルダー、間隔、期間を指定します。保存時に通信せず、次の定期収集または「今すぐ収集」で取得します。アプリ停止中は更新しません。「設定」の「定期収集を停止する」で全体を停止できます。停止後は予約済みの自動AIも送信前に拒否し、手動収集・手動解析は別に操作できます。

- Bluesky：キーワード（例 `Go lang:ja`）。固定 `https://api.bsky.app/xrpc/app.bsky.feed.searchPosts` の top / latest 各100件まで。
- Mastodonタグ：公開HTTPSサーバーのオリジン、カンマ区切りの1〜3タグ。各40件までをOR収集します。
- Mastodonアカウント：サーバー内のローカル名。lookup後に初回40件、以降は最新側から最大3ページ×40件を取得します。収集範囲外の投稿は取りこぼす可能性があります。

間隔は15〜1440分、期間は1〜168時間です。定期巡回は1分ごとに期限を確認します。「調べる」のSNS調査で結果を選び、直近30収集回、反応数順位、関連タグを確認します。スコアは `いいね + 再投稿×2 + 返信`、上位40件。同点は公開日時と投稿IDで決定します。サンプル内の値であり、網羅的な流行やSNS間の比較を保証しません。

投稿は通常の記事として保存され、既読・スター・フォルダー・案件・根拠を共用します。左の「⋯」→「SNS調査・収集設定」で調査画面へ移動し、間隔・期間・AI観点・自動解析を編集できます。検索条件の変更は新しい情報源として登録します。停止中も個別の「今すぐ収集」は使えますが、自動解析は停止します。

失敗した回は一部の記事も順位も保存せず、前回成功結果とエラーを残します。429は同じMastodonサーバーまたはBluesky全体で待機を共有し、手動でも迂回しません。その他の失敗は15分から指数バックオフ。429待機は既定15分、最大7日です。画像・添付・埋め込みは取得しません。SNSはRSSのOPMLへ含めず、完全バックアップで保存します。

## AI 接続を用意する

「設定」→「AI接続」でプロバイダを選び、モデルと上限を保存します。初期状態は全接続が無効で、既定モデルを選びません。保存だけでは生成しません。

OpenRouter / OrcaRouter の選択はSNS話題抽出の接続先を切り替えます。Ollama local/cloud の設定を編集しても、その選択は変更しません。各設定は独立して保持し、予約済みジョブは元のprovider/model/版に固定します。予約後にその接続設定を変更・無効化した場合、そのジョブは送信前に失敗化します。

- OpenRouter：起動環境の `OPENROUTER_API_KEY`。固定 `provider/model` と構造化出力対応モデルを指定します。自動ルーターと `:online` は受け付けません。送信先は固定 `openrouter.ai/api/v1/chat/completions`。`data_collection=deny`、`require_parameters=true`、`allow_fallbacks=false` と単価上限を送信します。
- OrcaRouter：起動環境の `ORCAROUTER_API_KEY`。OpenAI / Google / xAI（grok含む）の構造化出力対応モデル。固定 `api.orcarouter.ai/v1/chat/completions` を使用し、OpenRouter固有フィールドは送信しません。処理IDとusageを確認し、即時費用がなければ読取り専用のgeneration照会を最大2回だけ行います。生成POSTは再送しません。
- Ollamaローカル：利用者がモデルを用意し、固定 `127.0.0.1:11434` で起動します。`OLLAMA_NO_CLOUD=1` 等でクラウドを無効化してください。モデル名と `/api/tags` のSHA-256 digestを設定し、料金は0とします。生成前に `/api/status` の `cloud.disabled=true`、モデルのdigest一致とremote_host/modelなし、runtime版を確認します。未対応statusでも送信を止めます。アプリはモデルをpullしません。
- Ollamaクラウド：固定 `https://ollama.com/api/chat`。起動環境の `FEEDASTROLABE_OLLAMA_TOKEN_FILE` で所有者だけが読める0600のregular fileを指定します。symlinkは拒否。ファイル上限4096byte。料金とUTC確認日を利用者が設定します。Windowsの所有者ACL検証は現時点で未対応なので、Windowsではこの接続を有効利用できません。

キーは画面・DB・入力・ログ・設定JSON・バックアップへ保存しません。`.env`は自動で読みません。利用者のシェル環境に設定してから `npm start`、またはその環境から配布アプリの実行ファイルを起動します。資格情報を変更した場合はアプリを再起動します。元版の `.env` やtoken fileを自動参照しません。

## 話題抽出と費用

SNSの結果から「重要トピックを抽出」を押すと、最大5件の話題名・重要度・要約・理由・未確認点・出典記事IDを生成するジョブを予約します。「収集・自動抽出を設定」で明示的に有効化した場合だけ、収集成功後にも予約します。

上位40投稿のうち、公開・送信可能な最大20件、各本文400文字、入力全体32KiBまでを選びます。タイトル、URL、公開日時、反応数、固定出典ID、評価観点を送信します。internal / restricted案件に関連する記事・根拠やそれを引用する非公開メモは対象から除外します。認証値らしい文字列の検出も行いますが、完全検出を保証しません。

初期値は1回0.10 USD、全provider共有でUTC1日1 USD / 24回、出力2048token、入力1 USD / 百万token・出力3 USD / 百万tokenの単価上限です。画面はUSD、内部は整数micro USD。料金が未確認のクラウドOllamaは使えません。保守的な入力token上限 `要求本文のUTF-8 byte数 + 256` と出力上限×設定単価で送信前に予約します。ローカルOllamaは費用0ですが回数は同じ台帳で数えます。

予約は接続先切替でリセットしません。翌日実行時は実行日にも予約します。失敗・中断・不明費用でも予約を戻しません。申告費用が予約を超えれば結果を拒否し、その費用を台帳へ保守的に反映します。実請求の保証ではなく、事業者の履歴も確認してください。

同じ収集回・接続設定版・SNS設定版は1ジョブです。失敗済みの予約は同じボタンで再送せず、再収集または設定変更で新しい入力として予約します。過去の成功結果は保持します。AI出力の真偽は未検証であり、出典IDの検証は主張の真偽の保証ではありません。

## 根拠を使った Ollama 調査補助

1. 「調べる」で案件の公開区分をpublic / internal / restrictedに設定します。初版からの案件は互換性のためpublicです。
2. 記事から根拠を保存します。案件の「出典付き調査補助」でlocal/cloud、要約・翻訳・比較・質問を選び、根拠を最大8件選択します。各根拠1200文字まで、入力byte+256が8192を超える場合は選択を減らしてください。
3. 「送信内容をプレビュー」で正確なAPI body、接続先、入力hash、費用予約を確認します。プレビューでは資料をモデルへ送りません。根拠がなければ不足と返し、モデルを呼びません。
4. 確認チェック後に「承認して生成を予約」を押します。プレビューは30分で失効。同じ承認は同じjobを返します。案件・接続設定・根拠の版や区分が変わると新しいプレビューが必要です。
5. 「生成履歴を再読み込み」で状態と結果を開きます。各claimの `[E番号]` は選択根拠だけを許可します。元資料と原出力は変更しません。「レビューを保存」でdraft / reviewed / rejectedと確認・修正メモを新しい版として保存できます。

クラウドにはpublic案件だけを送信します。同じ記事・根拠hashが他のinternal / restricted案件やその根拠参照メモに関係する場合も拒否します。ローカルは非公開案件を扱えますが、クラウド無効化とdigest検証を必須にします。送信直前に再検証し、送信中は最大90秒SQLiteの書き込みを排他するため、他の編集が待機する場合があります。資料の命令はデータとして扱い、tools・検索・shell・ファイル操作を提供しません。

## 復元と制限

schema1から2への移行前バックアップはデータ先のmigration-backups、復元前バックアップはbackupsへ保存します。backup1/2を受け入れます。復元後は全AI接続・自動解析を無効にし、queued/runningをfailedへ変更して再送しません。設定JSONの読込みもAIを無効にし、現在の予算消費は保持します。

1生成ずつ、総期限90秒、応答1MiB、POST再送なし。未完了20件、ジョブ/プレビュー履歴各1万件、画面のジョブ表示は直近100件。現版のOllama設定はlocal/cloud各1つで、元版の複数名前付きprofileは後続移植です。予算も現版は全接続の共有台帳です。
