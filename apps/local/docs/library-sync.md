# Web と local の同期

「設定」→「Web と同期」で Web のサイトURLを入力し「同期を有効にする」を選んで保存します。「今すぐ同期」で開始できます。起動中は1分ごとに再試行します。初期状態は同期しません。同期を停止しても local のデータ・送信待ちは残り、RSS/SNS収集と読書・実装済み調査機能を単独利用できます。全機能移植の完了を意味しません。

Cloudflared / Cloudflare Access が hostname 全体を Entra ID で保護する前提です。アプリ専用アカウントや同期APIキーは追加しません。認証が必要な場合は「接続先を開く」で同じ Electron セッションへログインしてから同期します。Access画面にはローカルIPCやファイル権限を渡しません。実環境のEntra/Access認証は別途受入確認が必要です。

同期対象は購読（URL・名前・フォルダー所属・停止/再開・収集間隔・SNSの取得条件）、記事本文、既読、スター、全体収集の停止/再開、最後の収集試行時刻とエラーです。Web/localのどちらでも変更できます。秘密情報、Access cookie、APIキー、AIジョブ、AI予算、調査案件・根拠、添付、閲覧履歴、表示テーマ、フォルダー順序・展開・ペイン幅は同期しません。観測のselector/baselineとSNSの取得cursorは端末ごとの状態です。Webのページ観測記事は読めますが、localでの観測実行は未移植です。

local の RSS 情報源メニュー「名前・設定を編集」では収集間隔（秒）も指定できます。収集の状態を受信しただけではネットワーク取得やAIジョブを起動しません。各端末は自身のスケジュールで収集します。同じ記事は購読URLとguidで重複排除します。

## 競合・失敗・復旧

初回は両ライブラリを結合します。既読・スター・購読の停止/再開は独立項目で、名前変更で停止状態を戻しません。本文の収集更新が状態を戻すことはありません。同一項目の同時変更は Lamport clock、同じclockではイベントIDの順で決定します。時計のずれで端末の現在時刻を優先しません。初期の未読・スターなしを変更として送り、既存の既読・スターを消すことはありません。

削除は相手側の購読と記事も削除します。購読停止は既存記事を残します。削除墓標を保持するため、古い再送で削除済みの購読が復活しません。再購読後も削除以前のイベントを再適用しません。URL変更は識別子変更として旧購読削除と新購読・記事の送信を行います。

通信エラー、認証切れ、redirect、HTML応答、不正JSON、未知プロトコル、過大な応答では送信済位置を進めません。成功応答の取り込みと送受信カーソル更新は同じDBトランザクションです。応答喪失後は同じイベントIDで再送します。接続先URLを変更すると相手のカーソルを初期化して手持ちの履歴を再送します。接続先が以前と別のライブラリへ変わった場合はエラーにし、意図した接続先か確認した上で設定をいったん空にして再保存します。

初回の同期用DB拡張前に `migration-backups/` へ整合したSQLiteスナップショットを保存します。Webの既存schema19・localのschema2へ追加テーブルを作り、元のIDと状態は維持します。既存localのSNS識別子はWeb互換へ移行します。バックアップは保管し、古いという理由では削除しません。

local の設定JSON v3には同期先URLを含めます。認証値・記事・送信待ちは含めず、読み込み後の同期は停止します。完全JSON v3は情報源ごとの収集設定を保持し、v1/v2の復元にも対応します。復元後は接続先とカーソルを消して独立ライブラリに戻します。Access cookieはElectronの専用セッション内に保存し、これらのJSONへ含めません。

## プロトコル v1

`POST /api/sync/v1/exchange` は `application/json` で `{version:1, hub:"", cursor:0, events:[]}` を受け取ります。応答は `{version:1, hub, cursor, more, events}` です。既存の `/api/v1` などの公開APIは従来どおりscope付きBearerキーが必要です。同期専用ルートだけがAccess認証へ委譲されます。Origin不一致とcross-site書込みを拒否します。originのポートを直接公開しない既存配備を維持してください。

イベントは `{id,clock,kind,key,value}`。IDは32桁のランダムhex、clockは安全なJSON整数。kindは `feed` / `article` / `read` / `star` / `delete` / `collection` / `polling` / `enabled`。keyは購読で `[url]`、記事状態で `[url,guid]`、全体収集で `[]`。イベントは100件まで、本文2MiBまで、転送は約8MiBのバッチで分割し、クライアントの応答読取り上限は10MiBです。UIの記事表示件数の上限ではありません。履歴は現版では圧縮・世代削除せず保持します。

SQL triggerによってUI/API/worker変更を同じトランザクションで記録します。受信中はecho用の新IDを発行せず、受信イベント自体を履歴へ保存します。本文や状態が購読より先に届いても保留した最新値を親の到着後に反映します。相手ライブラリの世代IDとカーソルを検査し、巻戻りを黙って受け入れません。

## 接続確認とエラー

同期前に本文を送らないGETでAPIの準備を確認します。未反映のWeb（404）は「Webを更新して再起動」、認証redirect/403は「接続先を開いてAccess認証」、DNS/TLS/タイムアウトはそれぞれの原因を表示します。チェックボックスは同期全体の有効/停止です。設定を保存するまで切替は反映されません。停止中は「今すぐ同期」を無効にし、ローカル読書・収集は続けられます。

デスクトップのmain通信処理を更新した後は、localアプリを終了して `npm start` で起動し直してください。画面の再読込みだけではmainの通信処理が更新されません。
