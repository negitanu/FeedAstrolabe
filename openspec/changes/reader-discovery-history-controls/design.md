## Context

現在は RSS URL を即時登録し、記事は公開日時降順で表示する。詳細リンク・POST・署名継続トークンに条件が分散している。既読／スター API はあるが複数選択 UI はない。

## Goals / Non-Goals

**Goals:** 指定順に5機能を完成する。リンク・フォーム・継続取得の条件を共通化し、テーマ・モバイル・キーボード・no-JS に対応する。

**Non-Goals:** 人気度の推測、外部検索索引、意味検索、AI生成、外部サービスへの送信は行わない。

## Decisions

1. RSS 探索は既存 fetch（DNS pinning・redirect 検証・時間/容量上限）を再利用。HTMLParser で alternate RSS/Atom リンクのみ抽出し、最大8候補の URL とタイトルを返す。選択候補をプレビューすると検証済み最新5記事を表示。署名・セッション束縛・15分期限付きプレビューから確定登録し、確定時に再取得・重複検査する。候補を全て自動取得する方式は遅延とリクエスト数を増やすため採らない。プレビューは購読・記事・既読を書き込まない。
2. 履歴は article_visits(article_id PK FK cascade, visited_at UTC microseconds) の最新閲覧1件を保存する共有ライブラリ。明示的な閲覧 POST を JS から送り、既読化・スター・API参照・一括既読とは分離。no-JS は記事内の履歴記録フォームで対応。履歴は閲覧日時の降順が既定、通常は公開日時降順。
3. 条件の正規化と order SQL / keyset を共通モジュールへ集約。新しい順・古い順と履歴順を allowlist で選び、同日時は id で決定。継続トークン・前後移動・read-next は同じ条件と順序。APIの既定順は変えない。
4. 詳細検索は通常 q を保持し、検索対象 title/body/both、追加 OR 語、除外語、日付 from/to、複数フィードを厳密検証。複数語は1行1語の literal match。q は従来の一つのフレーズ、OR の各行はいずれか、除外は全て否定し、各グループは AND。日付は表示TZの暦日を UTC の半開区間へ変換し公開日時不明を除外。フォーム・URL・署名scopeを共通化。任意SQL・正規表現は受け付けない。
5. 複数選択は明示チェックと選択数・操作バー。選択対象は描画済みの任意記事、全条件一括既読とは分離。100件までを1原子的処理にし未知ID・重複・対象外・CSRF失敗で全件変更なし。APIとUIの状態変更を共通関数へ集約。DOM差分更新時も選択を保持し、別条件へ遷移時は解除。no-JS は選択フォームの通常POSTと再描画。

## Risks / Trade-offs

- 外部サイトの大量探索 → 最大8候補、HTMLのalternateのみ。認証や外部索引は使用しない。
- 履歴と既読混同 → 記録専用 POST、説明とテストを追加。
- 新条件の欠落によるスコープ拡張 → 共通hidden-fieldsテンプレート、正規化されたscope・厳密検証。
- 日付境界・更新中の履歴 → UTC正規化と固定keysetで検証、同じIDを二重描画しない。
- DB移行 → 非破壊の追加テーブルのみ。既存記事・状態・順序・根拠を保持。旧schemaのbundle復元を確認。

## Migration Plan

schema18から19へ追加テーブルと索引を作る。実データ移行前には整合したbundleを取得し、全writerを止めてコンテナ更新。失敗時は旧画像と事前bundleで復元する。新依存は追加せず、既存仮想環境で検証する。
