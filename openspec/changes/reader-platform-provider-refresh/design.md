## Context

以下は2026-10-24の変更開始時点の背景。承認済み設計は実装・検証済みで、末尾の実装結果に採用版と検証範囲を記録する。

- 現行の読者画面は `preferences.page_size` とLIMIT/OFFSETでページングする。APIもpage_sizeを利用するため、画面の廃止とAPI互換性を分けて扱う必要がある。
- `feeds.enabled` と `update_subscription()` は存在する。購読停止のメニュー・手動収集・待機ジョブの統一制御は不足している。
- `folder_positions` とフォルダードラッグは存在する。個別フィードの表示順は未保存で、左ペインは固定幅248px。
- 設定の情報源入口は `settings_pages.PAGES`、`navigation.settings_groups()`、登録済み項目一覧、作業手順リンクに分散する。
- AI抽出は `social_ai` とOpenRouter専用HTTP層。入力スナップショット、予算予約、ジョブ来歴は既にあり、これを維持して拡張する。
- アプリイメージはPython 3.14の固定digest、rendererは同じ基底にPlaywright/Chromiumを加える構成。トンネルは `cloudflare/cloudflared:latest`。
- バックアップはDB・資料を含む復元用バンドル。今回の設定エクスポートは別形式とする。

## Goals / Non-Goals

**Goals:**

- 日常の整理・購読操作を左ペイン内で完了させる。
- 記事をページ区切りなく読み、本文の往復でも一覧を失わない。
- AI接続をプロバイダ選択へ統合し、既存の費用・来歴管理を維持する。
- Python 3.15と最新依存へ更新し、役割ごとにHardened Imagesの適用可否を判断する。
- 一貫した形式で設定をJSONダウンロードできるようにする。

**Non-Goals:**

- 公開APIのページング廃止、設定インポート、記事・研究資料全体の移行、秘密情報のエクスポート。
- OrcaRouter専用の別設定ページや、プロバイダをまたぐ暗黙のフォールバック。
- ローカルOllama調査補助をリモート事業者へ自動移行すること。今回の接続切替対象は既存OpenRouterを使うAI抽出で、共通レジストリを将来の呼び出しにも使える設計にする。

## Decisions

### 1. リーダーの継続取得と画面状態

内部バッチは30件とし、固定の描画上限ではなく通信・描画の単位としてのみ扱う。UIのページ表示、ページリンク、ページ件数の設定欄を削除する。公開APIとDBに残るpage_sizeは互換用で、読者画面の件数を制限しない。

継続キーは `(published_at, id)` の降順タプル。署名付きトークンに、バージョン・正規化済みの全条件・末尾タプルを含める。フォルダー名は空文字・大小文字・Unicodeを完全一致で扱う。継続取得も通常画面と同じフィルター検証を通し、署名・型・条件不一致は400とする。新着が既存カーソルより上に増えても、OFFSETずれを起こさない。新着を先頭へ反映するのは明示的な再読み込み時とする。

IntersectionObserverで末尾近くを検知して一度に1リクエストだけ実行する。カードは共通サーバーテンプレートから取得し、IDで重複排除する。失敗時は既存カードを残し「再読み込み」操作を出し、無限自動再試行をしない。「さらに読み込む」はキーボード操作と自動観測非対応時の代替であり、ページ番号は付けない。

本文は一覧を差し替えず、共通の本文フラグメントを取得する。選択、本文を閉じる、記事の前後移動、既読にして次へ、ブラウザー戻る／進むで、一覧バッチ・位置・選択・表示形式を維持する。並行応答はリクエスト世代番号／中断で整理し、古い条件の応答を新しい一覧へ追加しない。

記事の既読／スターはPOST成功後にカードと本文を調整する。未読条件で既読になったカードなどは取り除き、次バッチを必要に応じて追加する。「全て既読」は描画カードのID一覧を送らず、サーバーで現在の全条件に対して更新する。

JavaScript無効時は同じ条件の全件表示を明示的に選択できる。旧pageパラメーターはページ境界として利用せず、条件と指定記事を保った通常の読者URLに正規化する。カーソルや読み込み済み件数を公開APIのページ契約へ混ぜない。

### 2. 購読停止・再開と収集経路

停止は登録削除ではなく `enabled=false`。UI表記は「購読停止」「購読再開」に統一し、既存のフィード設定の定期取得チェックも同じ状態に連動する。停止済みの項目はアイコン／状態で区別するが、常時説明文を増やさない。

既存の原子的購読更新を利用し、有効状態だけを変更する。URL・interval・フォルダー・ページ観測基準・SNS条件・AI評価観点を同時変更しない。停止操作・再開操作自体は収集を開始しない。

スケジューラー、単独／全体の手動更新、page_jobs、SNSの自動抽出予約を点検し、新規ディスパッチ直前にも状態を確認する。未実行の関連ジョブは取消／実行見送りとし、すでに外部リクエストを開始した処理は安全に完了可能とする。手動AI抽出は既存公開記事の明示的な利用として扱い、購読停止だけを理由には禁止しないが、自動抽出は停止する。旧ジョブ記録・監査履歴は削除しない。

### 3. 左ペインのD&Dと順序モデル

共有DBへフィードIDをキーにした表示位置を追加する。位置はフォルダーごとの連続した順序としてサービス層で検証する。新しいDB移行番号は実装時の最新schemaに対して割り当てる。既存表示順を移行時に確定し、新規フィードはフォルダー末尾へ追加する。

フォルダーの並べ替えとフィードの並べ替え・移動は同じ操作部品を使い、行種別を明示的に区別する。フォルダーはフォルダー間にだけ挿入する。フィードは同一フォルダー内の前後、または別フォルダー内の位置へ挿入できる。閉じたフォルダー名へのドロップは末尾への移動とし、自動展開しない。

書き込みはBEGIN IMMEDIATEと収集との共通ロックで、最新の所属・対象存在・移動位置を再検証してから、所属と移動元／先の順序を同じトランザクションで確定する。名前変更・別タブでの削除・移動と競合した場合は失敗を返し、UIはサーバーの順序へ戻す。記事IDに関わる更新はしない。

タッチは専用ハンドルからドラッグし、行の他の領域ではスクロールできる。上下矢印・Home・Endで同じフォルダー内の位置を変え、右クリックメニューのフォルダー移動で非ポインター操作を補完する。Escape・pointercancelで未確定操作を取り消す。ドラッグ中にリンク移動や開閉が発生しないようにする。

### 4. 左ペインの幅

境界にフォーカス可能な `role=separator` を置き、左右キーで16pxずつ、Home/Endで許容範囲の端へ移動できるようにする。既定248px、下限200px、上限480px、主ペイン最低360pxを目安に、実際のviewportで上限をさらに制限する。

幅はブラウザーのバージョン付き表示設定に保存する。DB共有の並び順と異なり、端末ごとの幅を他の端末へ押し付けない。700px以下では既存のモバイル折りたたみレイアウトを使い、保存済みデスクトップ幅を適用しない。ストレージ拒否、不正値、画面縮小時も既定／clampで動作させる。

### 5. 情報源管理入口の整理

設定一覧・設定内ナビゲーションから `feeds` を除き、登録済み項目の情報源グループも除く。「集める」の登録後の作業リンクは読者画面へ向ける。案内のためだけの新ページは作らない。

旧 `/settings/feeds` は読者画面へ303。既存の `/settings/items/feeds/:id` は共通編集フラグメントの取得先とJavaScript無効時のフォールバックとして残す。URL・ページ観測・SNS条件の編集機能自体を削除しない。フォルダー名は記事表示、開閉矢印は開閉、右クリック／「⋯」は操作、という役割を維持する。

### 6. 一つのAI接続画面

設定のOpenRouter入口を「AI接続」(`/settings/ai`) に置き換える。最初の入力はプロバイダ選択。続けて選択先のモデル、認証設定済み状態、対応能力、必要な利用上限を表示する。プロバイダごとに画面を分けず、非選択先の入力欄を常時並べない。旧OpenRouter URLはOpenRouterを選択した共通画面へ移す。

`provider_id` は `openrouter` / `orcarouter` のレジストリで解決する。既存Ollama調査補助プロファイルとの機能差を曖昧にせず、呼び出し先決定・資格情報・payload生成・結果正規化を共通インターフェースに分離する。モデル名や通信パラメーターを一律に流用しない。

資格情報は `OPENROUTER_API_KEY`、`ORCAROUTER_API_KEY` で外から渡す。保存するのは事業者IDと非秘密の設定、ジョブには資格情報の種類への参照だけとする。環境変数の値をDB・ブラウザー・出力JSON・ログへ複製しない。通信先はプロバイダごとの既知HTTPSホストに固定し、既存のDNS pinning・サイズ・時間制限を共用する。

OpenRouter固有のprovider/data_collection/料金条件はOrcaRouterへ送らない。OrcaRouterは公式APIの `https://api.orcarouter.ai/v1` を対象とし、構造化出力の実対応をモデル単位で確認する。初期提供は能力と価格を事前に確認できる固定モデルを基準とする。自動ルーター別名は実モデル・構造化出力・最大費用を検証できる場合に限り選択可能とし、検証できない場合は理由を表示する。

OrcaRouterでは費用のopt-inヘッダーを送り、`usage.cost_usd`、レスポンスの `X-Orca-Request-Id` を個別に扱う。必要なら決済参照GETで精算を照合する。直後の404は少数回・短時間のGETのみ再試行できる。費用取得のために生成POSTを再送しない。実額不明時は予約額を維持し、無料として記録しない。料金上限はアプリの予約・利用制限であり、事業者が強制できない課金上限を保証すると表示しない。

日次の回数／費用はプロバイダをまたいで合算する。切替で利用枠はリセットされない。ジョブにはprovider・model・設定revisionを確定して保存し、実行時の画面上の選択から再解決しない。既存ジョブと履歴にはOpenRouterを補完し、既存入力ハッシュや来歴を破壊せず移行する。キーがなくなったジョブは別事業者へ逃がさず明示的に失敗する。

### 7. 最新イメージ・Python・依存の方針

`latest` は**新しい安定版を取り込む取得方針**として基本にする。Pythonの要求は3.15系なので、一般latestが3.16系へ進んだ場合やDHIが系列別タグのみを提供する場合には、その役割だけ最新3.15タグを使う。過去の固定digestを更新せず使い続ける構成は廃止する。ビルドではpullして解決したdigest・Python実版・パッケージ実版を記録し、その記録で検証／ロールバックできるようにする。未検証のlatestを稼働中サービスへ自動反映する機能は今回追加しない。

app/web/worker/observer、renderer、tunnelを役割別に評価する。DHIは利用権・pull可否・対象アーキテクチャ・Python 3.15・glibc/共有ライブラリ・非root・healthcheckを検証したものを優先する。ビルドにshellやパッケージ管理が必要ならdev variantを使い、対応するruntimeへ必要物だけ移す。rendererのChromium依存を満たせない場合はその役割だけ公式イメージを使う。DHIのPython 3.15タグやcloudflaredイメージが現に使えるとは、この仕様策定時点では断定しない。

Pythonは実装時点の3.15最新安定パッチとする。2026-10-24に確認した公式リリースページは3.15.1。実装時には再確認する。パッケージは直接・間接・テスト用をまとめて安定版で再解決し、成功した正確なバージョンをconstraintsへ記録する。無制限のバージョン指定で起動のたびに変える方式にはしない。

cryptography/cffi/greenletなどのネイティブ依存とPlaywrightに注目し、Linux arm64/amd64のwheelまたは再現可能なビルド、対応Chromium起動を確認する。3.15非対応依存のために黙って3.14へ戻したり、prereleaseを混ぜたりしない。必要な制約は名前・版・理由を列挙する。`requires-python` とローカル検証環境も更新する。

### 8. 設定エクスポートの範囲と形式

設定一覧のヘッダーに「設定をエクスポート」を置く。新ページを作らず、セッション認証・CSRF付きPOSTから添付JSONを返す。DB設定は一つの読み取りトランザクションのスナップショットで取得し、ブラウザーから渡す表示設定は専用スキーマで検証する。Cache-Control:no-store、Content-Disposition:attachmentを付け、サーバー上の公開ファイルとして保存しない。

形式の外枠は `format: feedastrolabe-settings`、`format_version: 1`、`exported_at`（UTC）、`app_version`、`db_schema_version`、`settings`、`references`、`omissions` とする。`settings` は以下を明示的な許可フィールドだけで構成する。

- `collection`: 既定間隔、定期収集の有効状態、初期表示、表示タイムゾーン、API利用上限など。
- `subscriptions`: フィードの種類・取得先・名前・フォルダー・有効状態・個別間隔・ページ観測／SNS／抽出条件。
- `library_order`: 完全一致のフォルダー識別とフィードIDを使う並び順。
- `ai`: 選択中プロバイダ、各プロバイダのモデル・料金予約条件、共通の日次利用上限。
- `connectors`、`models`、`notifications`、`backup`: 公開情報サービス、調査補助モデル、通知、バックアップの非秘密の構成値。
- `watchlists`、`security_watches`、`network_watches`、`ai_watches`: 案件／対象を参照する保存検索・ウォッチの設定。参照は `references` へ出し、記事・研究内容を展開しない。
- `topic_settings`: SNS分野別の評価観点と自動抽出設定。
- `presentation`: 当該ブラウザーの外観・記事表示形式・フォルダー開閉・左ペイン幅。

.env、APIキー、キーhash/prefix、認証ヘッダー、トークン、セッション署名鍵、接続先の埋込資格情報、秘密ファイルの内容と保存場所は出力しない。任意のURL・通知パラメーターに資格情報が埋め込まれる場合は、フィールドを除外／マスクし `omissions` に非秘密の理由を記録する。DB行を丸ごとdict化して出力する方式は採らない。資格情報の有無は必要な箇所だけ真偽値で示せる。

記事本文・根拠・メモ・生成入力／出力・ジョブ・ログ・利用実績・キャッシュ・復元用DBは含めない。出力は設定の保管・比較に使うもので、この変更にインポート／自動復元は含めない。既存のOPMLと完全バックアップの役割は維持する。

## Risks / Trade-offs

- 無限読み込みでDOMが増える → まず通信バッチを小さくし、数千件の測定を受入に含める。必要なら画面外カードを高さ保持で退避する。ただし全記事へ到達でき、戻る位置・アクセシビリティを失わないことを優先する。
- 停止直後のin-flight処理 → 未実行ジョブと実行中リクエストを区別し、停止を取り消し保証と誤表示しない。
- 右クリック依存 → 同じ「⋯」・キーボード操作・既存の編集フォールバックを維持する。
- DHIの利用条件・ブラウザー依存 → 役割別の実測と、理由付き公式イメージfallbackを残す。
- OrcaRouterの費用・機能差 → provider別の能力検証と費用精算を行い、OpenRouterの保証を転用しない。
- 広範な設定JSONに秘密が混入 → 明示allowlistと実際のダウンロードバイトの非混入テストを行う。
