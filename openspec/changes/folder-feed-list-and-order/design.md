## Context
フォルダーはfeeds.folderの文字列で識別され、Jinja groupbyが常に名前順へ戻している。開閉はdetailsとブラウザーストレージで保存されている。空文字の未分類と「未分類」という名前のフォルダーは別物である。

## Goals / Non-Goals
**Goals:** フォルダー名から正確な所属フィードの記事一覧を開く。順序を任意に変更・永続化する。矢印の開閉、既存記事表示、モバイルとキーボード操作を維持する。
**Non-Goals:** フォルダー階層化、名前変更、フィードの個別並べ替え。

## Decisions
- `/folders?folder=<正確な名前>`に記事一覧を設ける。同じ読者シェルと記事クエリを使い、所属フィードの全記事を新しい順に表示する。未読・スター・検索・案件・タグ・ページ送り・本文・次の記事・一括既読に完全一致のフォルダースコープを適用する。存在しないフォルダーは404。
- summary内の名前を通常リンクとし、左矢印の開閉と分離する。JavaScript無効でもリンクとdetailsのキーボード操作を利用可能にする。
- スキーマ17でfolder_positionsを追加する。既存フィードと記事は変更しない。並べ替えはBEGIN IMMEDIATE内で現状を再読込し、指定フォルダーを移動して順序を保存する。表示時は存在するフォルダーだけを採用し、新規フォルダーは保存済み順序の末尾に名前順で追加する。
- `/settings/folders`に上へ・下へ・指定位置の操作を置く。マウス、タッチ、キーボードで任意の順序へ移動できる。ドラッグ専用操作にしない。
- サーバーでグループを生成し、Jinja groupbyによる再ソートを廃止する。位置の保存はCSRF付きPOSTのみ。入力と戻り先はアプリ内で固定する。

## Risks / Trade-offs
- フォルダー名に空文字や特殊文字 → 完全一致・パラメーター化SQL・自動エスケープ、ラベルで空文字を未分類と区別。
- 別画面からの追加・削除 → トランザクション内で最新の集合を読んで移動。消えた対象は404、範囲外の位置は入力エラー。
- DB更新 → 既存DB移行とバックアップ・復元の回帰テストを実行。DBバージョン期待値を17へ更新。

## Migration Plan
自動マイグレーションで空の順序テーブルを追加。並べ替え前は既存同様の名前順。全テスト後にコンテナを再構築・再起動し、HTTP配信を読み取り確認する。
