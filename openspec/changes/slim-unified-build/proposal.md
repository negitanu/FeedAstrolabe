## Why

Five overlapping requirements files and two Dockerfiles duplicate dependency pins and runtime setup. The renderer additionally installs full Chromium even though every browser job uses headless shell, increasing its image size.

## What Changes

- Consolidate all existing pinned dependencies into requirements.txt and remove the other four requirements files.
- Select app, renderer and test roots through standard dependency groups in the existing pyproject.toml, using the single requirements file as constraints.
- Consolidate Dockerfiles into one shared runtime stage and app/renderer targets; keep default builds lightweight and exclude test/browser dependencies from app.
- Install only Chromium headless shell in renderer, suppress generated bytecode and retain cache cleanup, isolation and pinned versions.
- Update Compose, CI instructions, documentation and build verification; measure image sizes against the previous verified images.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `local-operation`: Add unified reproducible dependency/build inputs with role-specific lean images.

## Impact

Requirements, pyproject metadata, Dockerfile, Compose build targets and verification/documentation. No app behavior, schema, credential or production-service changes.
