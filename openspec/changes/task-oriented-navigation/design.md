## Context
UI は Flask/Jinja。既存の変更が多数あるためフォームのPOST処理・権限・CSRFを保持する。

## Goals / Non-Goals
Goals: 全画面で共通の5分類、作業順序の案内、設定への最大3クリック。
Non-Goals: 外部サービスの設定をアプリから代行すること、データ移行。

## Decisions
- ナビゲーション定義をPythonに集約し、共通ヘッダーと作業ハブで共有する。スマートフォンでも5分類を折り畳まない。
- 設定索引からカテゴリのフォームや既存機能のアンカーへ直接移動する。既存 /settings とPOST URLは互換維持し、カテゴリ指定時に必要なカードだけ表示する。
- 個別設定は全件の索引を設け、ページ送りに依存させない。案件・ウォッチ・フィードには直接リンクを付ける。
- クリック数は任意のアプリ画面から設定入力欄の表示まで。保存や確認操作、入力・スクロールは含まない。外部Cloudflareや.envなど画面外の設定は案内を表示する。
- フォームを囲む折り畳みは設定リンクの着地点で開いた状態にし、JSに依存しない。

## Risks / Trade-offs
- 索引の件数増加 → カテゴリ別整理とブラウザー内検索で探せる一覧を維持する。
- 既存アンカーの破損 → レンダリングされたリンク先とアンカーを自動検証する。
- 設定が元画面にも残る → 元画面から共通の設定索引への導線を付ける。

## Migration Plan
DB変更なし。テンプレートとルートの更新で導入・取り消しができる。
