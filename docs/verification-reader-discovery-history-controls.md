# RSS探索・閲覧履歴・リーダー操作の検証

2026-10-25 JST。OpenSpec change: `reader-discovery-history-controls`。アプリ0.16.0、schema19、Python3.15.1。機能比較時の基準は0.15.0/schema18であり、過去のFeedly比較記録とは区別する。

## 実装範囲

1. 既存の安全な取得処理を再利用するサイトURL探索。HTML alternateを最大8候補、選択した候補のタイトル・URL・最新5記事を確認後に購読。15分・同一セッションの署名プレビューを確定時に検証し、再取得する。
2. 最新の本文閲覧を保存する `article_visits`。POSTによる記録と、既読／スターの更新を分離。履歴一覧、再閲覧順、再起動・削除・bundle復元に対応。
3. 公開日時の昇順／降順と履歴順を共通化。追加読み込み、同日時のID順、前後記事、read-nextに同じ順序を使う。
4. 通常のリーダーにタイトル／本文、追加OR語句、除外語句、公開日、複数情報源のフォームを追加。既存qのliteral semanticsと、POST form優先を維持。表示TZの暦日をUTCの半開区間へ変換する。
5. 描画済み記事を最大100件選び、既読／未読／スターを原子的に変更する。API/UIの更新処理を共通化し、全て既読との対象を分離。追加読み込み・本文往復・差分更新・no-JSでも選択を扱う。

## 検証方法

テストは既存の `.venv` 内で実行し、新しい製品依存は追加していない。Playwrightは合成データのローカルHTTPに接続する。各ブラウザー実行は個別の一時DBを使い、実利用者の購読・記事・根拠を変更しない。

- 探索：通常HTMLの複数・相対・重複候補、8件上限、直接RSS、購読前のDB非変更、改ざん／期限／別セッション／CSRF、重複確定、取得エラー。
- 履歴：GETや既読・スターでは増えず、訪問POSTだけで更新。再閲覧順、記事削除、再起動、schema18からの移行、bundle復元、差分更新後も閲覧日時を保持。
- 並び順：74記事・同日時・複数バッチ、keysetのscope違い、本文前後・read-next、history順。
- 詳細条件：タイトル／本文、OR／除外、複数情報源、UTC/JST境界、公開日時不明、無効日付・逆転・未知ID・重複値・文字数、検索条件を維持する全て既読。
- 複数選択：選択件数、未知／重複／対象外／過多ID、CSRF、全件原子性、API契約の維持、複数カードのreconcile。
- 実ブラウザー：375px／1280px × light／dark／systemの6条件。詳細検索→本文→履歴、選択→追加読み込み→一括スター、チェック保持、横方向の収まり、JSエラーなし。no-JSは375px／1280pxの2条件。
- 既存表示の回帰：320／768／1024／1920px、モバイルの初期記事位置、1行表示の高さ、タイルと本文パネルの配置。選択バーは未選択時に隠して初期の記事領域を確保する。

回帰検証で見つかったフォームの `action` 項目名との名前衝突は、送信先をHTML属性から取得する形で修正した。チェック欄による1行表示の段落ちも列定義を更新し、既存の密度要件を維持した。旧テストの「入力は4個固定」は、通常の検索・並び順の5入力と折り畳み内の詳細条件を区別する検証へ更新した。
