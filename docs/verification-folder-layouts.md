# フォルダー折り畳みと記事表示形式（2026-10-21）

以下は当時の種類→フォルダー階層の検証記録です。現在は後続の[フォルダー優先・コンパクト表示](verification-compact-reader.md)で、フォルダーを最上位にし、開閉設定をv2形式へ移行しています。

## 変更

- 各フィード種類の中にフォルダーのdetails／summaryを追加しました。未分類も折り畳め、購読件数と1件以上の未読件数を表示します。種類が異なる同名フォルダー、空欄と文字列の「未分類」は独立した保存対象です。フォルダー名は従来どおりHTML escapeします。
- 開閉はブラウザー／originごとのlocalStorageに保存します。従来の種類別設定は互換のまま保持し、フォルダーは別のversion付きキーを使います。選択中のフィードの種類とフォルダーは一時的に開き、保存済みの閉状態を上書きしません。サイドバーのリセットは両方の保存を解除します。
- 記事一覧の表示形式に標準・1行・タイルを用意しました。同じDOM・記事順・検索条件・ページ送り・本文リンク・既読／スターのPOSTを使用し、表示形式だけを変更します。選択はブラウザー／originごとに保存し、1行は省略表示、タイルは既存のテキスト要約を使うレスポンシブなグリッドです。外部画像の取得は追加していません。
- 保存データのversion・型・サイズ・許可値を検査し、フォルダーの保存時に消えたフォルダーのキーを除去します。保存機能が使えなくてもネイティブの開閉と現在の画面での表示切替は利用できます。JavaScript無効時は標準表示とネイティブの開閉を提供し、動作しない切替ボタンは隠します。
- DB・API・依存パッケージ・本番サービスの変更はありません。スクリプトは既存のnonce方式で許可し、CSPと本文のサニタイズを維持しています。

## 検証

実Chromiumで、フォルダー名のescape、件数、異なる種類の同名フォルダーと空欄／文字列の未分類の独立性、キーボード開閉、選択フィードの展開、保存状態の復元・リセットを確認しました。壊れたJSON、不明version、不正な型、過大な保存データ、保存アクセス拒否、JavaScript無効時も確認しています。

記事の表示切替前後のリンク順序、フィード／未読／検索条件とページの保持、本文表示・閉じる操作、ブラウザー状態の復元、既読／スターPOSTの永続化を確認しました。表示切替だけでは記事の状態を変更しません。

幅1440px、390px、本文ペインありの1280pxで1行／タイルを確認し、ページ横方向のはみ出しがないことを実測しました。1行のタイトル省略・行高、デスクトップの複数列タイルと狭いペインの1列表示、操作ボタンを検査し、スクリーンショットを目視確認しました。

スクリーンショットは検証用データで `/private/tmp/feedastrolabe-reader-presentation/` に保存しています。本番のライブラリ・資格情報・公開Tunnelは使用していません。
