# 作業別ナビゲーションと画面内の設定

全HTML画面の上部に「読む・集める・調べる・まとめる・設定」を常設する。PCとスマートフォンで名称・並びを統一し、現在の領域を色・下線・`aria-current`で示す。スマートフォンでもメニューを開く操作は不要。

## アプリ全体のツリー

```text

├─ 読む /                         記事と情報源の閲覧
│  ├─ 初回：情報源を選んで始める → 集める
│  ├─ すべて・未読・スター・最近読んだ記事・詳細検索・並び順・案件/タグの絞り込み
│  ├─ フォルダー名 → そのフォルダー内の全フィードの記事一覧 → 記事本文
│  │  └─ 左の矢印：開閉／名前：記事一覧／右のハンドル：並べ替え
│  ├─ フォルダー・フィードの右クリック／⋯ → 名前変更・設定・移動・削除
│  │  ├─ 前後の記事・元記事
│  │  └─ 案件/タグへ関連付け・根拠として保存
│  ├─ 表示形式・フォルダーの開閉
│  └─ フィードの右クリック／⋯ → 設定・フォルダー移動・購読停止/再開・削除
├─ 集める /navigate/collect       情報源の選択と作業順

│  │  └─ この分野の設定 → 画面内の設定ダイアログ → 収集結果に戻る
│  ├─ ページの変化 → /sources/new/page → 画面内の設定ダイアログ → 変更記事
```

「集める・調べる・まとめる・設定」は機能一覧へ入口を集約する。上段の重複ショートカット枠と、下部の見出しを繰り返すページ内リンクは置かない。選択中の上部ナビゲーションと同じページ名の大見出しも表示せず、本文は機能グループから始める。mainのアクセシブル名とナビゲーションの現在位置は維持する。PCは2列（設定は広い画面で3列）、モバイルは1列とし、行頭を揃える。全画面共通のメインナビゲーションと、設定エクスポートなど固有の操作は維持する。

## 3クリックの定義と経路

任意のアプリ画面を起点とし、編集対象の入力欄が利用可能になるまでのリンク選択・折り畳み展開を数える。入力、スクロール、保存・削除の実行、内容の承認は到達後の操作。

- 全体設定：上部の「設定」→ 設定項目。2クリック。
- 情報源：左ペインの右クリック／「⋯」→ 操作。2操作。削除はダイアログ内で対象を確認して実行する。
- 案件・ウォッチ：上部の「設定」→ 登録済み項目。2クリック。作業一覧からも右クリックで編集できる。
- 「情報源の管理」は設定から除去した。追加は「集める」、編集は左ペインのメニューへ集約する。
- SNSの収集条件・自動抽出条件は、同じ分野の画面内の設定ダイアログにまとめる。追加の折り畳み操作は不要。
- 共有タグも全件表示し、100件の一覧制限で設定が隠れないようにする。
- アーカイブした案件は案件設定で再開する。編集可否の制約は維持する。
- Cloudflareや秘密情報はアプリ外で設定する。画面で編集する代わりに「接続情報・実行環境」で管理場所を案内する。

表示形式とフォルダー開閉は「読む」を選べば操作できる。画面内の設定ダイアログの索引はページ送りなしで表示し、名前での絞り込みとブラウザーのページ内検索も利用できる。

## 画面の責務と操作完了

設定画面は専用URL・見出し・現在位置を一致させる。AI接続からSNS登録画面へ移動しない。保存後は同じ設定を表示し、関連する作業へのリンクを末尾に示す。AI接続の入力エラーでは入力内容を保持し、部分更新や生成を実行しない。

登録は情報源の種類ごとに独立した画面を使う。登録手順と実行ボタンで次の操作を示し、重複する見出しや説明を置かない。SNSは登録→収集→結果→画面内の設定ダイアログ→結果の順に進める。調査ウォッチ作成は案件と対象を名前で選択する。要約・レポートは案件を引き継ぐ。モデルや案件がない場合は準備への入口を示す。

`navigation.py`で入口と作業順、`settings_pages.py`で設定フォームと登録画面、`context-actions.js`で共通メニュー・ダイアログを管理する。既存のPOST処理・CSRF・外部送信の明示承認を維持する。`/navigate/settings`は`/settings`へ、旧`/settings?section=...`は対応する専用設定へリダイレクトする。旧ページ内フラグメントは利用せず、アプリ内リンクを専用URLに更新した。

検証範囲と実行結果は[専用設定画面の検証記録](verification-dedicated-settings-workflows.md)を参照。

## フォルダーを使う

サイドバーのフォルダー名を選ぶと、所属する全フィードの記事を新しい順にまとめて表示する。未読・スター・検索・案件/タグ・追加読み込み・本文・前後の記事・一括既読にも同じフォルダー条件を引き継ぐ。空の未分類と「未分類」という名前のフォルダーは別々に扱う。左の矢印だけでサイドバー内のフィードを開閉する。フォルダー名のクリックや記事・フィードへの移動では開閉状態を変更しない。

フォルダー右側のハンドルをドラッグして並べ替える。順序はDBに自動保存され、再読み込みや別の端末でも維持する。ハンドルにフォーカスして上下矢印・Home・Endでも移動できる。Escapeやタッチ中断は取り消し、保存失敗時は並びを戻してエラーを表示する。専用の表示順ページと入口は削除し、旧URLは記事一覧へ戻す。

フォルダーを右クリック、または「⋯」を選ぶと「記事を表示」「名前を変更」を使える。名前変更は所属フィード全件と表示順を同時に更新し、記事・既読・スターと開閉状態を維持する。同名フォルダーへの変更は統合せずエラーにする。

フィードのメニューは「設定」「フォルダーを変更」「削除」。同じ画面内のダイアログで編集する。削除対象の記事と既読・スターも消えることは実行前に明示する。設定索引と各作業画面の案件・保存検索・脆弱性／ネットワーク／AIウォッチも同じメニューとダイアログを使う。Shift+F10、メニュー内の矢印・Home・End、Escapeに対応する。

保存エラーは入力を残して表示する。複数フォームを編集した場合、別フォームの保存で未保存内容を消さない。保存後に閉じると元の条件の画面を更新し、削除などで元のフォルダーが存在しなくなった場合だけ記事一覧へ戻す。JavaScript無効時の既存編集リンクは従来のサーバー画面へフォールバックする。全体設定（外観・API・連携など）は引き続き「設定」から2クリックで到達する。

## 外観と共通UI

「設定」→「外観」でライト・ダーク・システム連動を選ぶ。初期値はシステム連動で、OSの配色変更に追従する。選択はブラウザーのCookieに1年間保存する。フォルダー順序は全端末で共有し、外観はブラウザーごとに選択する。

テーマはサーバーでHTMLに反映し、CSSで配色を適用する。JavaScriptが無効でも動作する。`presentation.py`にテーマ検証とスクリプト用nonceを集約し、`static/css/`に共通色・基礎・リーダー・調査・SNS・ナビゲーション・設定・フォルダーのスタイルを分割する。固定の白背景・文字色を意味別の色定義に置き換え、フォーム・エラー・グラフにも同じ配色を使う。

装飾用の英語ラベル、重複するページ名、設定カードの説明、共通の「設定のあとに」説明を削除。識別子・版・件数・エラー・外部送信の確認・入力条件は保持する。通知とドラッグハンドルは共通テンプレートを使う。

## 連続読み込みと左ペイン

記事一覧にページ番号・前後ページ移動・表示件数設定はない。末尾が近づくと続きを追加し、通信失敗時は「再読み込み」で続ける。本文・前後の記事・閉じる・ブラウザー履歴でも一覧を維持する。JavaScriptが無効な場合は「すべて表示」を利用できる。

フォルダーとフィードのハンドルはドラッグと上下矢印/Home/Endに対応する。別フォルダーへのドロップでフィードを移動し、閉じたフォルダーは展開しない。並び順はDBに保存して端末間で共有する。左ペイン境界はドラッグと左右矢印/Home/Endで幅を変え、端末ごとに保存する。

購読停止は新規収集と待機中の自動処理を止め、記事・既読・スターを残す。すでに始まった外部リクエストは完了する場合がある。再開後は保存済みの間隔で通常収集に戻る。

AI接続と設定エクスポートの範囲は[AI接続・設定出力](ai-providers-and-settings-export.md)を参照。

記事一覧ではj/kで移動、oまたはEnterで本文、mで既読切替、sでスター、nで次の未読、/で検索欄へ移動できる。入力中やメニュー操作中は記事ショートカットを実行しない。旧`/reading-prefs`による任意のPOST既読化は維持するが、通常の本文GETは既読を変更しない。表示条件から外れる記事の直接表示は404とする。

### 記事一覧とフロート詳細

記事一覧の通常クリックで、一覧幅とスクロール位置を保ったまま右側に詳細を重ねて表示します。詳細は独立してスクロールでき、モバイルでは画面幅に収まります。「閉じる ×」で一覧に戻ります。記事の中クリックは元ページを新しいタブで開き、既読状態を変更しません。詳細タイトルも元ページへの別タブリンクです。元URLがない記事ではリンクを表示しません。上側の前後移動・件数表示と「元記事を開く」ボタンは廃止し、本文末尾の前後移動を利用できます。詳細表示時に自動で既読と閲覧履歴を保存し、未読一覧でも本文を維持します。「既読にして次へ」は廃止しました。

### 記事詳細の表示順

アイキャッチ（取得できた場合）→タイトル→時刻→既読／未読・保存→横線→記事の説明→横線→調査案件・タグ・根拠保存→前の記事・件数・次の記事の順です。既読にして次へ／一覧へボタンはありません。アイキャッチは元ページのOGP/Twitter Cardから取得し、幅480px（狭い画面では縮小）で表示します。画像がない・取得失敗の場合は画像欄を省略します。画像取得は本文読み込みを待たせず、既存の安全な取得処理と同一オリジン配信を使います。

詳細パネルの上端は記事欄の上端に合わせ、共通ヘッダーとパンくずを覆いません。スクロール・画面サイズ変更に追従し、本文は画面下端までの範囲で独立してスクロールします。

最近の閲覧、並び順、詳細検索、複数選択と RSS 探索の手順は[読む・集めるの拡張](reader-productivity.md)を参照。
