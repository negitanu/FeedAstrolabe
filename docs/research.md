# 調査ワークスペース

`/workspaces` で案件を作成し、目的・問い・進行状況を記録します。公開区分は公開／内部／制限付き（既定は内部）。同じライブラリの利用者と API キーはすべての案件を閲覧できます。区分による外部送信の制御は後続段階で追加し、現在は送信機能を持ちません。

案件詳細でフィードを関連付けると、そのフィードの現在・今後の記事を表示します。ライブラリの記事本文から、記事だけを複数の案件に追加することもできます。直接の記事リンクとフィード経由の記事は重複表示しません。直接リンクを外しても、関連フィード経由の記事は表示されます。

メモは Markdown で記録し、確認した事実／情報源の主張／仮説を区別できます。この分類は記録者の判断です。保存・アーカイブ・再開のたびに版を記録します。過去の版は編集できません。複数画面で同じ版を編集すると、後の保存は409となり、UIには未保存の入力を保持します。最新版と比較して再保存してください。タグの関連付けは版本文とは別の共有メタデータです。

案件のアーカイブは閲覧を保持し、編集を停止します。再開時はアーカイブ解除だけを行います。元の購読、収集、記事の既読・スターには影響しません。メモも個別にアーカイブ・再開できます。購読削除やページ記事の保存期限では関連する記事リンクも消えますが、案件・メモは残ります。記事の不変な根拠保存は第七段階で追加します。

タグは案件・記事・メモで共有し、名称変更はすべての関連箇所に反映されます。名前は1〜80文字、SQLite NOCASE により ASCII の大文字小文字を区別せず重複を拒否します。日本語やその他の Unicode は同じ文字列で比較します。1件の案件・記事・メモに関連付けるタグは最大100個。画面の選択肢は最新100案件／フィード、名前順の先頭100タグ（現在の検索条件のIDは選択肢に含めます）。その他はページ付き API を使えます。

案件・メモのタイトルは1〜120文字、目的・問いは各10000文字、メモ本文は100000文字まで。API は1〜100件、UI は30件ごとにページ送りします。HTML はエスケープしたうえで Markdown を変換し、許可リストで再検査します。画像・スクリプト・埋め込みは表示しません。

バックアップは既存の SQLite backup/restore を利用し、案件・関連・メモ履歴・タグをすべて含みます。現在の DB はスキーマ v5。v1〜v4 のバックアップは復元時に v5 へ移行します。復元前には web・worker・observer を停止してください。旧イメージへの切り戻しには移行前 v4 バックアップを使います。

実 HTTP の検証用ライブラリを作成するには：

```sh
.venv/bin/python scripts/verify_research.py
# 検証専用の日本語画面を一時的に保持する場合
.venv/bin/python scripts/verify_research.py --serve-port 5012
```

検証データは一時ディレクトリのみを使い、終了時に破棄します。利用者の DB や資格情報は使いません。ブラウザー確認はこの検証画面で行えます。
