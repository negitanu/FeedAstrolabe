# フォルダー優先とコンパクト表示（2026-10-21）

## 変更

フォルダーをフィード一覧の最上位にしました。同じフォルダーのRSS・X・Mastodon・ページ観測をまとめ、フィードごとに種類ラベルを表示します。フォルダーの購読数・未読数も種類をまたいで集計します。空欄の未分類と文字列の「未分類」は別の保存対象です。フォルダー名の大文字・小文字も保持します。

開閉状態はブラウザー／origin単位のv2形式で保存します。旧v1形式からの移行では、統合先の全種類が閉じていた場合だけ閉状態を引き継ぎ、一部の種類だけが閉じていた場合や新しい種類がある場合は開きます。選択中フィードのフォルダーは一時的に展開し、保存済みの閉状態を上書きしません。リセットで新旧の開閉設定を解除します。記事の表示形式の保存は変更していません。

案件・タグ・検索をテーマの配色・高さ・角丸・フォーカス表示に揃えました。一括既読と表示形式も同じ操作エリアにまとめ、見出し・上部バー・サイドバー・カードの余白を削減しました。標準／タイル表示はタイトルと要約を最大2行にし、本文で全文を読めます。reader以外の設定・調査画面のレイアウトには影響しません。

スマートフォンでは「ライブラリ・フォルダー」を閉じた状態から始め、記事を先に表示します。開いたナビゲーションは画面内でスクロールできます。入力欄・操作ボタン・フォルダー見出しは40px以上の高さを確保しています。JavaScriptが無効ならナビゲーションは開いたままで、ネイティブの開閉と標準表示が利用できます。

## 同一データでの比較

検証用の60記事・12フィード・4フォルダーを使い、同じ画面幅・高さ・スクロール位置で比較しました。「完全表示件数」はカード全体がviewport内に入る件数です。記事の長さや保存済み表示状態によって値は変わります。

- PC 1440×900：最初の記事の上端422→149px。標準2→5件、1行9→20件、タイル4→12件が完全表示されました。
- スマートフォン390×844：初期ナビゲーションをコンパクトにし、記事の上端1958→351px。標準0→2件、1行0→10件、タイル0→2件が完全表示されました。
- 全モードで横方向のページはみ出しはありませんでした。変更前後のJSONとviewportスクリーンショットは `/private/tmp/feedastrolabe-compact-review/` へ保存し、PC・スマートフォンを目視確認しました。

## 機能検証

混在フォルダーの件数・ラベル・HTML escape・開閉保存と旧形式の移行、キーボード／タッチ操作、選択フィード展開、保存アクセス拒否、不正な保存データ、JavaScript無効時を確認しました。案件・タグ・検索のGET条件と、一括既読のPOST対象範囲を実ブラウザーで検証しています。

幅320／390／768／1024／1280／1440／1920px、本文ペイン、全記事レイアウトで操作と横方向のはみ出しを検査しました。既存の記事移動・既読／スター・CSP・API認証の回帰検証も対象です。本番のライブラリ・資格情報・公開Tunnelは使用していません。

最終検証は実Chromium有効で406テスト成功、スキップなしでした。OpenSpec全29項目strict、git diff --check、追跡対象／新規候補の秘密情報パターン検査、Gitleaksのsource／tests／docs検査も成功しています。検証専用のlocalhostプレビューは確認後に停止し、本番サービスは再起動していません。
