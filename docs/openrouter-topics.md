# AI接続による重要トピック抽出

Mastodon／BlueskyのSNS調査で保存した投稿から、重要な話題を日本語で最大5件抽出します。反応数に加えて、分野との関連性・新規性・影響範囲・具体性・根拠を評価します。話題名、重要度0〜100、要約、判断理由、未確認点、元記事へのリンクを表示します。AIの評価は未検証であり、出典の検証は主張の真偽の保証ではありません。

## 設定

1. OpenRouterまたはOrcaRouterでAPIキーを発行し、ローカルの `.env` に `OPENROUTER_API_KEY` または `ORCAROUTER_API_KEY` を記載します。チャットやGitには貼りません。別の資格情報ファイルは不要です。
2. `docker compose up -d --build` で反映します。キーはWebとworkerだけへ渡し、observer・renderer・Tunnelには渡しません。基本のTunnel tokenはこれまでどおりです。
3. 「設定」→「AI接続」でプロバイダを選び、構造化JSON出力対応の固定モデルID `provider/model`、予算を設定して有効にします。OrcaRouterはOpenAI／Google／xAIの対応モデルを対象とします。以下のOpenRouter固有の条件はOrcaRouterへ転用しません。[モデル一覧](https://openrouter.ai/models)で対応と料金を確認してください。自動ルーター、`:online`など追加処理を有効にするモデル指定は受け付けません。`:free` は指定できます。
4. 分野を開き、投稿収集後に「重要トピックを抽出」を押します。workerの次の巡回で実行します。画面を再読み込みすると結果を確認できます。
5. 分野ごとの「評価観点・自動抽出を設定」で重視する観点を指定できます。「定期収集後に自動抽出する」を有効にすると、最新の収集回を自動解析します。

標準Composeのworkerを使うため追加サービス・ライブラリは不要です。GETで有料処理を実行しません。全体・分野の定期収集を止めると自動解析も止まります。手動解析は定期収集の停止中も使えます。対象プロバイダの設定を無効にすると、その接続先の手動・自動解析を停止します。非選択プロバイダの設定は保持し、予約済みジョブは元の接続先へ固定します。日次利用枠は両プロバイダ共通で、切替ではリセットしません。詳しくは[AI接続の設定](ai-providers-and-settings-export.md)を参照してください。

APIキーやモデルを自動作成せず、既定モデルも選びません。キーがない場合、または有効化前は既存の投稿収集・反応数ランキングだけが動きます。既存のOllama調査補助は独立した機能です。

## 送信範囲

最新の成功したSNS収集回の上位40投稿から、送信可能な最大20投稿を選びます。投稿ごとのタイトル・本文先頭400文字・公開日時・反応数・記事IDと、分野名・評価観点・収集期間を送信します。入力全体は最大32KiBで、それを超える前に選択を止めます。画像、添付、案件名、メモ、記事の個人タグ、資格情報は送信対象に含めません。

internal／restricted案件のフィード・記事・固定根拠・メモ・引用に関連付いた記事は除外します。送信直前にも公開区分を再確認します。認証値らしい文字列を含む抜粋も除外しますが、秘密情報の完全な検出を保証するものではありません。公開調査だけに使用してください。今回の送信JSONは詳細画面から確認できます。

送信先は選択に応じて `https://openrouter.ai/api/v1/chat/completions` または `https://api.orcarouter.ai/v1/chat/completions` に固定し、APIキーはAuthorizationヘッダーだけに付けます。DB・API応答・画面・ログにキーを記録しません。公開IPへ接続を固定し、リダイレクト・圧縮応答・1MiB超の応答を拒否します。モデルにツールやWeb検索を要求しません。上流エラー本文や生の例外は保存・表示しません。

OpenRouterでは `data_collection=deny` と構造化出力の対応を必須にして送信します。これはOpenRouterのプロバイダー選択条件であり、OpenRouterアカウント自身のログ・プライバシー設定は別途確認してください。条件を満たすモデル／提供元がなければエラーになり、条件を緩めて再送しません。

## 費用と失敗時

初期上限は出力2048 token、1日24回、1回0.10 USD、1日1 USDです。回数・日次予算は全分野で共有します。提供元の入力料金は1 USD／100万token、出力料金は3 USD／100万token以下、リクエスト単位料金は0に限定します。これらは選択可能な料金上限であり、実際のモデル料金を示す値ではありません。高額なモデルを選ぶ際は対応する上限を設定してください。

入力JSONのUTF-8バイト数＋256を保守的な入力token上限とし、出力上限・単価上限から費用を見積もって、送信前にUTC日次予算と回数を予約します。予算に収まらない予約は送信しません。APIが返すtoken数と費用も検査し、画面にAPI申告費用を表示します。料金上限の対象外のアカウント手数料などを含む実請求額は利用した事業者の利用履歴を確認してください。OrcaRouterでは費用が即時に得られない場合だけ決済参照GETを最大2回行い、費用不明時も予約額を維持します。生成POSTは再送しません。

同じ収集回・モデル設定版・分野のAI設定版は、ボタン連打・巡回・再起動でも1回だけ実行します。失敗・タイムアウト・中断時には請求済みの可能性があるため、自動再送せず予約額も戻しません。再実行したい場合は新たにSNS投稿を収集してください。モデル設定や評価観点を変更した場合も別の解析になります。

429はRetry-After／レートresetを考慮した接続先ごとの待機になります（既定15分、上限7日）。待機後も失敗済みの同じ予約は再送しません。401はキー、402は残高・利用上限、404はモデル名・構造化出力・価格条件を確認してください。応答JSONや出典IDが不正、ツール呼び出し・拒否・途中切れ・利用量不明の場合は結果を採用しません。失敗時は前回成功結果を、その旨を表示して保持します。

最大1件ずつ、90秒以内の処理です。接続待機は10秒、非ストリーミング応答ヘッダーの待機は最大60秒、読み取り中は10秒単位で総期限を守ります。公開区分と送信を競合させないため、送信中はSQLiteの書き込みロックを保持します。他の編集が待機／busyになる場合があります。

## 保存・復元・API

現在はschema v18へ自動移行します（AI抽出はv16、プロバイダ別設定と予約先固定はv18で追加）。既定は無効で、移行だけでは送信しません。正確な入力・ハッシュ・出典抜粋・モデル・利用量・抽出結果はDBと根拠bundleに含まれます。SNSの直近30収集回の保持に連動し、古い収集回の削除で対応するAI履歴も削除されます。元記事・根拠は書き換えません。

復元時は両プロバイダのモデル設定を保持したまま無効にし、分野の自動解析も無効にして、未完了予約は失敗にして再送しません。キーはバックアップに含まれません。復元した実行内容を確認してから再度有効にしてください。v18を旧アプリへ渡さず、ロールバックには更新前のバックアップを使用します。

- `GET/PATCH /api/v1/social-research/ai/config`：全体設定、キー有無、本日の予約額。PATCHは`expected_revision`必須。価格・費用は整数micro USD（1000000＝1 USD）、単価はmicro USD／100万tokenです。
- `PATCH /api/v1/social-research/{feed_id}/ai/settings`：`expected_revision`（topic.ai_revision）、`ai_enabled`、`ai_criteria`。
- `POST /api/v1/social-research/{feed_id}/ai/jobs`：空のJSON `{}` で予約（202）。同じ収集回・設定の予約を再利用します。
- `GET /api/v1/social-research/ai/jobs/{job_id}`：正確な入力・出典・状態・結果・利用量。
- 既存 `GET /api/v1/social-research/{feed_id}` の `analysis.latest` と `analysis.success` に直近予約と成功結果を追加します。

変更はwrite-scoped APIキーまたはUIのCSRFが必要です。ライブラリは共有で、readキーを持つ利用者も保存した解析内容を閲覧できます。分類は利用者別のアクセス分離ではありません。
