# Mastodon／Bluesky のSNS調査

ライブラリの「SNS トレンド調査」から、分野名・SNS・検索条件・フォルダー・収集間隔・対象期間を登録します。登録時には通信せず、workerの次の巡回または「今すぐ収集」で取得します。標準Composeのworkerが処理するため追加サービスやAPIキーは不要です。全体の「定期収集」を有効にしてください。

- **Bluesky**：キーワード検索。例 `人工知能 lang:ja`、`cybersecurity`。公式 `https://api.bsky.app/xrpc/app.bsky.feed.searchPosts` を利用し、上位・新着を各100件まで取得します。サーバー欄は空欄にします。
- **Mastodon**：公開HTTPSサーバー（例 `https://mastodon.social`）と、ハッシュタグをカンマ区切りで1〜3個指定します。例 `AI,機械学習`、`security,infosec`。`#` は省略可。各タグの公開タイムラインを最大40件取得します。複数タグはORで、同じ投稿を重複カウントしません。
- **Mastodonアカウント**：従来どおり設定画面で公開アカウントを購読できます。初回40件、以降最大3ページずつ差分を取得します。ローカルアカウント名を指定してください。

収集間隔は15分〜24時間（既定30分）、対象期間は過去1〜168時間（既定24時間）。全体停止・個別停止・指数バックオフが適用されます。CLIや全体の短い間隔を使ってもSNS調査の定期収集は最低15分です。手動更新は個別停止中も利用できますが、API待機を尊重します。検索語とタグはSNSサーバーへ送信します。公開調査の条件だけを登録してください。

## 結果の読み方

収集した期間内の公開投稿を重複排除し、`いいね + 再投稿×2 + 返信` のスコア順に上位40件を表示します。同点は投稿日時とIDで順位を決めます。関連タグは、収集サンプル内でタグを含む投稿の件数です。いいね数の増加率や全SNSの総投稿量を表すものではありません。

収集時刻・対象期間・サンプル件数・新規記事数・直近30回の成功履歴を保持します。新規記事数はその購読で初めて保存した投稿の数です。順位と反応数は収集時点のスナップショットで、投稿タイトルと既読・スターは現在の保存状態を表示します。過去のランキングは保存しますが、画面/APIは最新ランキングと各回の件数・タグを返します。

記事はRSSと共通の一覧で閲覧・検索・既読・スター・案件分類・根拠化できます。再取得で同じ投稿の本文が更新されても記事IDと既読・スター、元の一覧順を保持します。履歴は30回、各順位は40件までですが、保存済み記事・根拠は通常の保持方針に従い残します。購読削除時には記事と調査履歴も削除されます（固定済み根拠は既存の保持方針に従います）。検索語／サーバーを変える場合は別の調査として登録してください。

## 重要トピックのAI抽出

OpenRouterを設定すると、収集した公開投稿を話題ごとに整理し、重要度・要約・判断理由・未確認点・元記事を表示できます。手動または収集後の自動解析に対応します。キーは `.env` の `OPENROUTER_API_KEY` に記載し、モデルと予算を画面で設定します。追加サービスは不要です。[設定と送信・費用の範囲](openrouter-topics.md)を確認してください。

## 取得範囲と失敗時

Mastodonは指定サーバーが把握する連合・公開範囲に依存します。公開APIへのアクセス制限があるサーバーでは401/403になります。未認証での全文検索は行いません。非公開投稿・ブーストを除外し、公開・未収載の対象投稿を保存します。Blueskyは検索インデックスの対象と反映時刻に依存します。件数が多い場合や巡回間隔より短い期間を指定した場合は投稿を取りこぼすことがあります。網羅的なトレンド、履歴の全件収集、SNS間の順位比較は保証しません。

2026-10-21の実接続では `public.api.bsky.app` の検索が403、`api.bsky.app` の同じ公式メソッドは200でした。検索用の固定接続先には後者を使用します。提供側の制限が変わった場合は401/403を明示して停止し、スクレイピング・別表記による制限回避・無制限リトライをしません。

途中の取得や応答検証に失敗した場合、その回の投稿・順位を保存せず、前回成功時の結果とエラーを表示します。429ではRetry-After／レートresetを尊重して待機します（既定15分、上限7日）。Bluesky全購読、Mastodonの同じサーバーの購読で待機を共有し、手動更新でも守ります。他の失敗は指数バックオフに従います。

接続は公開IPへのHTTPSに限定し、DNSで確定したアドレスへ接続します。リダイレクト・5MiB超の応答・不正な投稿ID／反応数を拒否します。本文はHTMLを無害化し、画像・添付・埋め込みリソースを取得しません。認証情報や上流のエラー本文を保存・表示しません。

## Xからの移行と起動

Xの新規登録と収集は終了しました。schema v15への更新で既存X購読は停止し、手動更新・再有効化も拒否します。保存済みX記事・既読・スター・根拠は保持します。旧 `FEEDASTROLABE_X_TOKEN_FILE` とXのトークンファイルは使いません。ローカルの秘密ファイルを自動削除することはありません。

データをバックアップしてから `docker compose up -d --build` で更新してください。基本の `.env` は引き続き `TUNNEL_TOKEN` だけが必須です。DB移行は起動時に実行されます。戻す際には更新前のバックアップと旧イメージを使い、旧アプリにv15 DBを渡さないでください。

設定・記事・調査履歴はSQLite／根拠bundleのバックアップに含まれます。[API仕様](api.md)に登録・結果取得の例があります。OPMLはRSS購読のみを出力します。
