# セキュリティ情報・公開識別子の外部連携

「セキュリティ」から案件ID、対象画面で登録したCVE対象ID、関心のある製品・版を指定してウォッチを作成します。CVEが公開済みであることを確認して識別子送信を許可し、必要な連携を有効にするとworkerが取得します。初期状態は全連携が停止で、実ライブラリの設定も自動で有効にしません。製品名・版・メモ・添付・引用は送信しません。案件のアーカイブやウォッチ停止で自動予約を止めますが、すでに明示予約した共有ジョブは別の連携設定で停止します。

CISA KEVは[同庁の公式ミラー](https://github.com/cisagov/kev-data)の固定JSONを取得します。カタログ版・公開日時・追加日・対応期限・CISAの対応文を保持します。取得できた版で未掲載でも安全性や未悪用を保証しません。ミラーはCC0で、更新間隔により本サイトと遅れがあり得ます。

[FIRST EPSS API](https://api.first.org/epss/)は公開CVE1件のscore、percentile、日付、API版を取得します。[EPSSの説明](https://www.first.org/epss/)に沿って今後30日以内に悪用が観測される予測として表示し、個別環境の被害確率とは区別します。モデル版はこの応答に含まれず、API版から推測しません。データがない応答はscore=nullで、0ではありません。FIRST／Empirical Securityに帰属し、[利用と帰属の案内](https://www.first.org/epss/faq)を表示します。

[CVE Services](https://cveawg.mitre.org/api-docs/)の公開GETを使用し、JSON5.xのCVE状態・説明・CNA／ADPごとのCVSS版・スコア・vector、製品／版の主張、修正／回避策と参照URLを分けて保存します。原資料の主張で、利用者環境の適用性を自動認定しません。© The MITRE Corporation。CVEデータの利用は[Terms of Use](https://www.cve.org/legal/termsofuse)に従い、帰属と条件へのリンクを保持します。公式参照にPoCが含まれても自動取得・clone・実行しません。

カードに3つの独立した指標を表示し、総合的な「確実さ」の単一スコアを作りません。固定根拠は選択したレコードの投影で、取得元・版・観測日時・応答ハッシュを含みます。KEV全体は容量制限したキャッシュにのみ置きます。取得失敗・キャッシュ期限切れ・新応答の根拠未保存は古い情報として表示し、直前の成功観測を保持します。キャッシュの最終確認日時と原観測日時は別です。

## 適用性と参照の確認

製品名が完全一致する場合でも「可能性あり」に留め、バージョン文字列だけでは影響を確定しません。確認済み判断には同じ案件の固定引用と理由を必須にします。判断は不変版を保存し、古いexpected_revisionや他案件の引用は原子的に拒否します。ウォッチ設定の編集後は旧判断を現行適用性から外し、履歴に残します。記録者と確信は自己申告で、資産スキャンをしません。

アドバイザリ／修正／PoC参照は、同じ案件の固定引用・人の確認・公開URLを保存するメタデータです。最大1000参照／案件。固定根拠の引用を作るには根拠画面を使用し、表示された引用IDを指定します。新しい公開観測の根拠は有効ウォッチの案件へ固定し、既存のキーワードウォッチリストでも照合できます。

## 取得・保存の上限

共通コネクターは登録済みの固定endpoint／入力だけを受け付けます。任意URL、ヘッダー、body、認証値は受け付けません。この3連携は公開APIなので認証ファイルを読みません。X等の既存秘密情報を流用しません。将来認証が必要なアダプターは別の送信先・credential file契約を設けます。

- キャッシュ24時間（設定1時間〜7日）、各provider100取得／UTC日（設定1〜1000）、最小60秒間隔。FIRSTの[公式上限](https://api.first.org/#rate-limit)より低い既定値です。
- 一度に逐次3ジョブ、最大3試行、指数待機と429のRetry-After（最大7日）。待機中は手動予約でも上限を回避しません。
- TLS証明書検証、公的IPのみ、DNS pinning、リダイレクト拒否、identity encoding、応答5MiB／30秒。DNS解決時間はOS resolverに依存します。
- キャッシュ合計16MiB、同時pending100、累計ジョブ10000、ウォッチ100／案件。上限時はジョブを拒否／待機し、直前の成功データを保持します。現段階に累計履歴purgeはなく、後段の運用管理で扱います。
- CVE投影はコンテナ21、各配列50まで、全体150000文字。省略を表示し、過大投影は成功キャッシュを置換しません。KEVは10000行まで、EPSSは要求した1CVEだけ。

通常workerに加え、1バッチは `.venv/bin/python -m flask --app feedastrolabe connector-jobs` で実行します。APIでジョブを予約してもHTTP request内では外部取得しません。読み取りキーは連携設定・予約・判断を変更できません。UI変更はCSRFに従います。

schema8更新前bundleを保存してwriterを停止し、schema9へ移行します。v6〜v8 bundleの検証付き復元もschema9へ移行します。外部観測／引用を保持する根拠はretentionから保護し、復元はconnector.lockも確認します。[復旧手順](evidence.md)を参照してください。
