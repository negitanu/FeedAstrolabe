# 入力境界の安定化

OpenSpec change: `input-boundary-hardening`。

## 発見した問題と修正

- フィード指定の整数変換に失敗すると「指定なし」と解釈され、一括既読や手動更新が全フィードに広がる。負数・0も一括既読で全体指定となる。省略・空欄だけを全体指定として扱い、不正指定は400で拒否する。
- 不正な表示条件を全記事へ置き換え、検索語を200文字で切り詰め、重複した条件の最初の値だけを採用していた。表示条件・検索語・案件・タグを一意に検証し、不正・曖昧な条件では記事状態を変更しない。
- SQLiteの符号付き64bit範囲を超える記事・フィードIDがDBバインドで例外となる。URL内の整数IDにも共通の範囲検証を適用し、0・範囲外は400、19桁超は整数変換前に404で拒否する。既存の調査APIの400契約を維持する。
- 存在しないフィードへのUI手動更新が0件成功として終了していた。404を返し、取得を開始しない。

有効なIDによる対象限定、空欄での全体操作、既読・スター、CSRF、API権限は維持する。スキーマ・依存関係の変更はない。

## 検証

- 修正前にID関連の24ケース、表示条件関連の6ケースで期待動作の失敗を再現。原子的な拒否、取得ゼロ、状態保持、有効/空欄の正常系を含む33ケースを追加した。
- 既存テストのUnixソケット依存2件はsandbox内で失敗したが、制限外で実parser・rendererの両方が成功した。ブラウザー依存の2件は引き続きskip対象。
- 非文字列の購読source_typeも調査したが、既存実装が400で拒否していたため修正対象から外した。
- 最終の全回帰テストは285件成功、ブラウザー依存2件skip。追加33ケースすべて成功。実parserとrendererのソケット試験も含む。
- OpenSpec全20項目の厳格検証、`git diff --check`、追跡ファイル288件の秘密情報パターン検査に成功。

## 反映

ソース修正とテスト用データでの検証。稼働中のライブラリ・コンテナには反映していない。既存の表示タイムゾーン等の未コミット変更を保持している。Cloudflare/X実接続の延期と既存の外部連携設定を維持する。
